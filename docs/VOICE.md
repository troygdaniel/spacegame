# Ship voice (optional)

The ship computer can speak the key events of a run in a calm female voice. It is **off unless the player pastes their own Deepgram API key**. With no key the game is exactly as before and nothing is sent anywhere.

## Decisions (Troy, 2026-11-13)
- Calm female voice. ~~Text-to-speech only: no speech-to-text, no push-to-talk.~~ **Reversed on 2026-11-17: see Listening below.**
- Key events only, short lines, one voice.

## Decision (Troy, 2026-11-17): the player may talk to the ship's computer
Troy asked for voice to text so he can talk to the ship's computer. This replaces the 13 Nov rule "no speech-to-text, no push-to-talk" for that one use and no other: the ship still speaks only the key events, and the bar characters are still typed to. The rules that made the voice safe are kept:
- **Never always listening: hold, wait for the ring, then it listens.** Hold **U** (T is taken in both places) in space or in a station: a ring around the U key cap on the screen fills (0.6 s). When it is full the microphone opens, with a red LISTENING mark on screen and a short sound at the start and at the end, and the key may be let go. It stops by itself after about 1.2 s of quiet that follows words, on U again (send now), on Esc (cancel, nothing sent), when the window loses focus, after 6 s with nothing said, and after 20 s at the most. A tap that does not fill the ring does nothing but show a one-line hint. (Troy, 2026-11-18, from his first play log: he tapped U first and the first press was lost to the browser's microphone question; the ring replaced hold-and-let-go. The microphone is still shut while the ring fills.)
- **Nothing is recorded or kept.** The sound goes in one request to Deepgram when the listening ends and is dropped when the call ends: not saved, not logged, not in the save file, no copy in memory.
- **Own key, own cost.** It uses the same Deepgram key as the voice (Settings > Keys), sent only to `api.deepgram.com` in the `Authorization` header. No Deepgram key means no listening and a plain line saying where to add one. The ship's computer also needs a chat key (OpenAI or Anthropic) to answer, with its own plain line. Settings > Listen says it may cost the player money. A session may listen for 10 minutes in all (`LISTEN.limit.minutes`), then a plain line says so; a reload starts the count again.
- **The words are shown before anything is done with them.** They appear on screen as soon as Deepgram has them and, after a 1.5 second pause in which Esc cancels them (U again says it again), they are handed to the ship's computer exactly as if they had been typed on the command strip's line (`shipcompSubmit`, `docs/NPC-CHAT.md`, `src/shipcomputer.js` and `src/cmdstrip.js`, the section below).
- **The browser is asked early, once (Troy, 2026-11-18).** The first launch from a station shows one line ("Voice: the browser will ask to use your microphone. Choose Allow on every visit."), then asks for the microphone once and stops the tracks at once (nothing is recorded or sent). The launch waits for the answer, so flight never starts with the browser's question up (a question nobody answers holds it 30 s at most). Skipped when the browser says granted or blocked already, when listening cannot work (no Deepgram key, switched off) and for ever after the one time. Blocked: the U key cap says "blocked", a press says so without a ring, and Settings > Listen says so; allowing it later in the browser is noticed without a reload.
- **The browser asks for the microphone.** Denied, no microphone, a page that is not a secure context and a game opened from a file each get a plain line. `127.0.0.1` is a secure context: `node tools/serve.mjs` asks once; opened from a file the browser may ask every time or refuse (Settings > Listen says so in one line).
- **What it is not:** not streaming (the words come a moment after the listening ends, not word by word; a WebSocket stream is a later card and changes nothing above), not a wake word, not a separate screen (the strip below is where it shows and where you type), and not for the bar characters.

## Listening (`src/listen.js`)
- **The press:** `LISTEN.s` is a small state machine: idle, ring (the key is down, the ring fills), opening (the browser may ask: the first time a plain line says so before it does), listening (the level meter tells words from quiet), stopping, hearing, review (the words wait their pause). Every async step checks `LISTEN.s.seq`, so a cancel or a new press makes an older answer fall on the floor. The numbers are in `LISTEN.limit`: `ring`, `silence`, `words`, `lead`, `talk`, `hold`.
- **The request:** `POST https://api.deepgram.com/v1/listen?model=nova-3&smart_format=true&keyterm=...` with the recording as the body, `Content-Type` the recorder's container (`audio/webm` where the browser has it; the codec note is left off) and `Authorization: Token <key>`. The keyterms are the game's own names (the ship computer, the ship models, the stars) so it hears them; a 400 is tried once more without them. 401/403, 402, 429, a timeout (15 s) and the network each have a plain line; the key is never in one.
- **Sends nothing:** a hold under a third of a second (a tap) and a recording with no data in it. A silent microphone is still sent (a level meter that could be wrong must never be why nothing is heard); when the answer comes back empty and the meter heard nothing, the line says "I heard silence" and names the microphone. An empty transcript is never handed to the ship's computer.
- **Keys:** window-level listeners in the capture phase, so an Esc that cancels the words does not also open the pause menu. The key is ignored while typing in a field and with Ctrl, Cmd or Alt held. No scene binds U (`tests/listen.mjs` reads the sources to prove it).
- **Settings > Listen:** the switch, the key, what is missing, the session's minutes, **Test microphone** (opens it for an instant so the browser can ask; records nothing, sends nothing) and the hint. The words are `content/text/ui.md` (`listen.use`, `listen.cost`, `listen.hint`).

## How it works (`src/voice.js`)
- **Key:** typed or pasted in Settings > Keys (Pause > Settings, or `V` on the title screen, which opens Settings at the Deepgram key). Stored only in this browser's `localStorage` (`longhaul.voice.key`, separate from the save file), inside try/catch. Never written to the repo, never logged, never put in an error message, sent only to `api.deepgram.com` in the `Authorization` header.
- **Speech:** `POST https://api.deepgram.com/v1/speak?model=aura-athena-en&encoding=mp3` with `{ "text": "..." }`. The mp3 is decoded with the game's own AudioContext and played through the master gain from `src/audio.js`, so the **volume slider and mute (M) apply** and the pads duck as usual.
- **Queue:** one line plays at a time, lines never overlap. A line that arrives while another plays is dropped, unless it is a warning (hostiles, hull, ship lost), which waits in a queue of two and expires after 6 seconds.
- **Cache:** every decoded line is kept in memory by its text, so a repeated line costs no second call. A line also has a cooldown so the same event cannot repeat within 8 seconds.
- **Failure:** a rejected key (401/402/403) switches the voice off with one message; three network failures in a row pause it for a minute. The game never stops or throws because of the voice. **A call that never answers is let go after `VOICE.wait` (10 s)** and counts as a network failure (card `space-game-sound-stops`): before, a hung request kept the line "on its way" (`VOICE.playing`) for as long as the browser waited, so nothing else was said and the music stayed ducked.
- **Cost note:** Settings > Keys says, in plain words, that it uses the player's own account and may cost them money.
- **Events come from watching the game, not from the scenes:** `voiceInstall(game)` (called from `main.js`) reads game state once a frame and hooks scene `create` events, like `installAudio`. The scenes have no voice code.

## Character voices (NPC chat, `space-game-npc-chat-voice`)
`voiceSay(text, prio, model, onStart)` takes an optional `model`, an Aura voice name. The ship computer keeps `aura-athena-en`; each bar character has their own in the `voice` field of `NPCS` in `shop.js` (JUNO `aura-luna-en`, TAMSIN `aura-athena-en`, DEX `aura-orion-en`, MOSS `aura-arcas-en`, SABLE `aura-stella-en`, IDA KETTER `aura-hera-en`; the table is in `docs/NPC-CHAT.md` section 2).
- **One queue for everybody.** A character reply is a priority 1 line: if the ship computer is speaking it waits behind it (the queue of two, 6 seconds), so voices never overlap. The same words in a different voice are a different line for the 8-second rule.
- **Not cached.** Only the ship computer's lines are kept in memory, because they repeat. A character's reply is free text and is spoken once.
- **The name goes into a URL, so it is checked** against `aura-<name>-en` (or `aura-2-...`). Anything else, such as a made-up or hostile name from a content file, falls back to the ship computer's voice and cannot add anything to the request.
- **`voiceSayThen(text, prio, model, start)`** is for the chat box, which shows the words along with the voice: `start(how)` runs once. `'audio'` when the voice begins, `'timeout'` after 1.5 seconds if it has not arrived yet (the audio then still plays, and `start` does not run again), `'silent'` at once when there will be no voice (no key, off, muted, refused), so the reply never waits for nothing. Prio defaults to 1. The bar chat box (`chatAsk` in `src/chat.js`) uses it: while the audio is on its way the dots keep going and the text box stays locked, then the reply types and the box opens. `tests/chat.mjs` part 6 checks this against a mocked Deepgram.
- Same rules as the ship voice: own key only, no key means no call, mute and volume apply, a rejected key switches voice off for both.

## Testing
`tests/listen.mjs` (plain Node) mocks the microphone, the recorder and `fetch`: no test records anything or calls Deepgram. It checks the request, that the key goes only to `api.deepgram.com`, that the microphone is closed before the call is made, that the audio is dropped after it, every refusal and failure line, the 1.5 second pause and Esc.

`tests/voice.mjs` mocks `fetch` in the page, so **no test ever calls Deepgram and nothing is spent.** It also checks the character voices: the voice name reaches the URL, a made-up name cannot, replies are not cached, a character waits behind the ship computer in order and never overlaps it, `voiceSayThen` starts the text with the audio, after 1.5 s when the audio is slow, and at once when there is no voice. It checks: no key = no call; with a key, the call goes to `api.deepgram.com` with the key only in the `Authorization` header; the cache stops a second call for the same line; lines do not overlap; a rejected key switches the voice off; the key is not in the page text or the console.

- **Voice choice:** Settings > Sound picks the ship computer's voice from five Aura voices (`VOICE_CHOICES` in `src/voice.js`; Athena by default, kept in `localStorage` as `longhaul.voice.model`); a new choice drops the cached lines. Hear it makes one call, when pressed.

## The command strip (`src/cmdstrip.js`, card `space-game-command-strip`; Troy, 18 Nov 2026)
There is no ship's computer screen. **I** opens one line at the bottom of the flight view (and of the station): type, Enter sends, the answer shows under it. **U** speaks into the same strip. Troy's decisions: the game does **not** pause while you type or speak (the ship keeps flying, and while the line has focus the flight keys never reach the game, because the field swallows its own key events); replies show as text and are spoken when the ship voice is on (`shipcompSay`, the 1.5 s start rule of `voiceSayThen`); he picked the **Quiet** first-look picture, so nothing lingers over the flight view.
- **What it shows:** the last two exchanges, dim; the command line (the key cap, the line, "Enter send   Esc back to flying"); the answer, three lines at most. The microphone states come from `listenView` (`src/listen.js`): LISTENING with the level, HEARING YOU, the words with their pause, a plain line for a refusal. The old floating LISTENING box stays shut whenever the strip can draw (`cmdstripVoice`).
- **Quiet:** after the answer the keyboard is already back (Enter gives it back at once, the ship is yours while it thinks). The answer stays 4.5 s and 35 ms a letter more (12 s at most), fades over 1.2 s, and goes into a history of six. The next line brings the last two back, dim. `cmdstripHold`, `cmdstripView` and the table `CMDSTRIP` are the numbers; `tests/cmdstrip.mjs` pins them with a fake clock.
- **An act** ("take me to Kepler-4b") is one plain line in cyan, then 0.7 s later the game runs its own function from the closed list (`src/shipcomputer.js`); Esc in that moment cancels it, and the Esc is not left for the pause menu.
- **Where it may open:** space or a station that is running and not leaving; not with a terminal, a talk, the shop, a jump charging or the navigation list holding the keys; not without a chat key. The first-run tip steps aside while it is up, and the HUD's edge arrows keep clear of it (`cmdstripZone`). It is plain DOM over the canvas, at game pixels 368 to 992, 64 px above the bottom.

## Curt lines (card `space-game-voice-curt`; Troy, 20 Nov 2026: "the voice scripts are too long")
**The rule for every spoken line, in both games:** one short sentence, about 12 words at most, the fact first, no pleasantries, no repeated information; keep the number or the name the player needs (a distance, the ore, the hull). A line that is both shown and said may be short for both; if the shown text must stay long, give it a short spoken form instead.
- **Where it holds:** the ship's event lines (`VOICE_LINES`), the characters' scripted lines and reactions (`content/npcs/*.md`, equal to the defaults of `src/shop.js`), the Campaign computer's lines (`camp.say`, `camp.no`, `camp.nav`, `camp.help`, `camp.lose.tip`, `camp.nudge`) and the MULE's and the Reaver's toasts, the computer's fixed answers (`src/shipcomputer.js`), and the rules the models are given (`SC_RULES`, the `SAY:` format, `CHAT_RULES`, the persona card).
- **A test holds it:** `tests/voicecurt.mjs` counts the words (a `{placeholder}` is one word) and fails on a line over 12 (the key list of `camp.help.keys` is allowed 17, by name). A new spoken line goes by the same rule.
- **Not under it:** the Campaign story lines (`camp.l1`..`l3`, 2-GEN's, they follow the same rule in their own card), text that is only read (help screens, tips, the mission board, error lines), and the STATE/HOW/KEYS blocks a model reads.
- **Short** says the first sentence only: a first sentence under 45 letters takes the second one too, and nothing is said past 120 letters in one go (it was 70 and 170).
- Every changed line, before and after: `docs/night/voice-curt.md`.

## Stopping the ship and shorter answers (`src/voice.js`, `src/shipcomputer.js`, card `space-game-voice-shorter`; Troy, 18 Nov 2026: "the ship is long winded")
- **Stop:** **U** while the ship speaks cuts the voice at once and starts the hold ring (he will usually want to talk next). **Esc** while it speaks stops the voice first; the pause menu gets the next Esc (the listener takes the first one in the capture phase). A **click on the strip** stops it too (the strip is clickable only while the ship speaks). The words stay: the strip keeps the answer up while the ship says it, and shows it its whole hold from the moment it stops. `voiceStop(how)` cuts what plays, drops what waits, and moves `VOICE.gen` on so a line still being fetched never plays.
- **Shorter:** the computer's rules, persona and limits said one or two short sentences (now one short sentence of about 12 words: see Curt lines above; the caps are still 160 tokens, 320 letters of words), and more (300 tokens, 700 letters) only when the pilot asks ("tell me more", "explain", "in detail", "step by step": `scWantsMore`).
- **Spoken replies** (Settings > Sound, kept in this browser as `longhaul.voice.spoken`): **Short** (the default) says the first sentence or two of the answer (`voiceFirst`: a first sentence under 45 letters takes the second one too, never past 120 letters; it was 70 and 170 before the card `space-game-voice-curt`), **Full** says all of it, **Off** never says an answer aloud. The strip always shows all of it. The key moments of a run are short lines of their own and are not affected.
- **The log:** one `voice_reply` line per spoken answer (`docs/PLAYLOG.md`): seconds heard, whether it was stopped and how, the mode, the letters said and the letters of the whole answer. Counts, never words. `tests/voiceshort.mjs` pins all of it with mocked audio.

## Campaign chatter (`src/campchatter.js`, card `space-game-campaign-chatter`; Troy: yes to radio chatter from the fighters, the X-Wing wingman feel)
The wing talks in the Campaign: "Splash one.", "Taking fire!", "Copy that.", "Going home.", "Missiles running low." One short fixed line each, said by one of the three pilots in his own voice and shown bottom left, beside the command strip, with the pilot's own name (`Wedge: Splash one.`; it was a callsign, `HAWK: Splash one.`, until card `space-game-b14-c17-radio-names`).
- **The calls** (`chatterEventOf`, plain numbers, `tests/campchatter.mjs`): a kill (`splash`: any ship that is not Earth's blowing up), a hit on a wing ship (`hit`; the carrier's own hits are the computer's warnings), an order carried out (`copy` for launch, attack, escort, guard; `home` for a recall; read from the `C.orders` counters, so a key, the strip and the map all count), a wave (`contact`; the mothership jumping in is `mother`; the belt level's ambush, second wave and mothership lines too, `CHATTER.says`), the magazine at one or none (`lowmissiles`), ore picked up (`ore`), and the story: the relic answering (`relic`), a convoy through (`convoy`), a cache gathered (`cache`).
- **Quiet by default.** Settings > Sound > **Chatter**: **Quiet** (the default) is one line in 8 seconds and the same kind of call not twice in 24 s; **On** is one in 3 s and 10 s; **Off** is silent (the words are not shown either). The setting is `longhaul.chatter` in this browser.
- **Never over the computer or a warning.** The computer's own lines (a `say` event of the sim: a warning, a wave, a convoy) hold the radio for 2.5 s; a call that answers one waits 2.8 s, so it follows it. A line that is playing (the computer, a warning) blocks it. **Nothing is queued:** a call that cannot be said when it falls due is dropped, and one that waited too long (a pause) is dropped too. The voice is `voiceSay` at prio 0, which is never queued and never waits behind another line.
- **Fixed lines.** `content/text/chatter.md`, keys `camp.chat.<call>.<n>`: 32 lines of 6 words or fewer, no number and no `{placeholder}`, so a line is the same every time and the voice pack card can record each one once (a line in each pilot's voice: 32 lines, 4 voices). A pack adds a line by giving the next `n`. The three `chatter.mode.*` rows are what Settings says when a mode is picked.
- **The voices** (`CHATTER.pilots`): the four recorded Aura voices, named by the callsigns they were recorded under: HAWK `aura-perseus-en`, ROOK `aura-angus-en`, VEGA `aura-orpheus-en`, LANCE `aura-zeus-en`. None is a voice the computer can be set to (Settings > Sound) or a bar character's. The voice pack records every chatter line in each of the four, and the callsigns are never shown or said.
- **The pilots** (`CAMP.pilots`: Wedge, Kara, Apollo; card `space-game-b14-c17-radio-names`): the line is shown with the pilot's own name. **How the voice map works:** `CHATTER.voiceOf` gives each pilot ONE of the recorded voices for good (Wedge HAWK's `aura-perseus-en`, Kara ROOK's `aura-angus-en`, Apollo VEGA's `aura-orpheus-en`; LANCE's `aura-zeus-en` is spare: recorded, said by nobody). So Wedge always sounds like Wedge, and no line is re-recorded. **Who speaks:** the pilot who was ordered answers an order ("Wedge, guard our miner." is answered "Wedge: Copy that."; an order to All pilots is answered by the leader, Wedge: `C.lastOrder`, `chatterOrderWho`), the pilot whose fighter was hit or who made the kill speaks for it (`chatterWho`), and any other call takes turns among the pilots who are out (never the same pilot twice in a row, and a line is not repeated at once). With no Deepgram key there is no voice; the words are still shown (unless Off).
- **Not here:** numbers in a line (a count, a distance), the Long Haul game, and the computer's own order confirmations ("Launching the wing."), which stay as they were.

## The voice pack (`src/voicepack.js`, `tools/voicepack.mjs`, `voicepack/`, card `space-game-voice-pack`; Troy, 20 Nov 2026: "should we record the voice lines that repeat to reduce costs? Yes")

**What it is.** Every FIXED line the game speaks (the ship computer's events and orders, the story and briefings, the warp lines, the wing's radio in each pilot's voice) is recorded once, into `voicepack/` as an mp3 named `<voice>-<hash>.mp3` (a hash of the voice and the exact words), with an `index.json` that says which words each file is. `src/voice.js` plays a line from there when it is there and calls Deepgram **only for a line that is not**: free text (the computer's answers, a character's reply) and a line with a number or a name the game's tables do not list. So a repeated line costs nothing, and **the game speaks its fixed lines with no key at all**: whoever takes the game needs no Deepgram key for the main lines (Settings says FIXED LINES where it said NO KEY). Mute, the volume and the voice switch still decide; a key Deepgram rejected, or a backoff after failed calls, is the key's trouble and not the pack's. A player with a key who picked another voice than the pack's (athena) hears their own voice live; one with no key hears the pack's voice, so everyone hears the main lines. With no index (or an empty one) the game is exactly as it was.

**The catalogue is derived from the content tables, not listed by hand** (`voicePackCatalogue()`, pure, in `src/voicepack.js`; card `space-game-voice-pack-derive`). Every key of `UI_TEXT` (the defaults of every `content/text/*.md`) is matched, first rule first, against `VOICEPACK_FAMILIES`: **spoken** (the game says it: a source and a voice) or **silent** (the game only shows it, and the reason in words). Spoken today: the computer's `camp.say.*` and `camp.no.*`, the autopilot's answers (`camp.nav.say`, `.stopping`, `.there`, `.no.*`), the help answers (`camp.help.*`), the lose card's cause and tip, the story, a mission's two briefing lines, the warp lines, the reveal's ending (`camp.end.*`) and the cards that follow (`camp.rank/sys/scout/anom.*`), and `VOICE_LINES` (the ship's events); the wing's `camp.chat.*` in each of the four pilots' voices (any pilot may say any line). A key is recorded when it is fixed, **expanded** for the values the game's tables enumerate (the outposts' and convoys' names, "Building 3 fighters", "Point scanned: 2 of 3", the warp destination and distance) or **skipped with its reason** and kept live (`--list --skipped` says which; a card adds a source with `voicePackSource({ id, voice, lines | keys })`). **A key that matches no rule is `unclassified`, and `tests/voicepack.mjs` and `node tools/voicepack.mjs --check` fail on it**: whoever adds a new family of lines says in `VOICEPACK_FAMILIES` whether the game speaks it, and a card that only shows some of a spoken family puts a silent rule with its reason ahead of the family. So a spoken line can no longer be left live by being forgotten (the reveal's ending was). The places that speak free or computed words (the computer's answers, a character's reply, the credits received, the accepted call's title, the debrief score) are written down as live in `VOICEPACK_LIVE`, and the test checks the speaking call sites against it.

**The tool.** Troy runs it himself, in a terminal, with his own Deepgram key; an agent never has it. The key is read from the environment (`export DEEPGRAM_API_KEY=...`) and nowhere else: never an argument (it is refused: it would sit in the shell history), never printed, never written to a file or the repository.
- `node tools/voicepack.mjs --dry-run`: the plan: lines, characters, an estimate of the cost (Aura 0.015 dollars and Aura-2 0.03 dollars per 1,000 characters: a guess, see deepgram.com/pricing). **No key is read and nothing is sent.** Start here.
- `node tools/voicepack.mjs`: the plan, then it **asks** (type yes), then it records what is new or changed, one line at a time, saving the file and the index after each; stop it any time and run it again. Over `--max-cost` (default 5 dollars) it refuses before asking; outside a terminal it refuses.
- **Incremental:** a line is named by a hash of its voice and its words, so a changed line is a new line, an unchanged one is skipped, nothing is recorded twice, and only what changed or is new is paid for. The text of the game is not final (the belt, missions, outposts, systems lines will change): run it again after each change. A changed line leaves its old file behind until `--prune` (asks) removes the stale files and entries.
- `--list` (every line and whether it is recorded; `--skipped` the lines that are not and why), `--check` (exit 1 while a line is missing or stale: for after a recording), `--voices a,b` (more ship voices: each is another set of the ship's lines), `--only SOURCE`, `--root`, `--dir`.
- At the size of today's text: about 320 lines and 8,300 characters, about 12 cents.

**Tests.** `tests/voicepack.mjs` (Node only, no network, no key): the names, the index (a hand edit cannot make a file say another line), the catalogue's completeness, the tool on stand-ins (the dry run reads no key and sends nothing; it asks; the key is in one header and nowhere else; incremental; a rejected key stops it; prune), and playback (no key plays a recorded line with no Deepgram call; a line that is not recorded is a call as before; the player's voice choice; mute). Once the pack is recorded, `node tools/voicepack.mjs --check` says it is complete.
